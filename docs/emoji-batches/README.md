# Пачки emoji для каталога (AGE-1465)

Оператор генерирует картинки бесплатно по подписке Gemini (сетка 3×3), приложение потом режет,
нормализует и привязывает их к товарам.

## Файлы

- `catalog-snapshot-2026-10-30.json` — общий каталог на 2026-10-30 (только названия), из
  резервной копии продовой БД `backups/before-ai-usage-counters.dump`.
- `candidates.json` — что добавить: распространённые продукты и бытовые товары по деревьям
  категорий Open Food Facts / USDA FoodData Central и крупных магазинов, без того, что уже есть в
  каталоге, и без синонимов. `redo` — существующие товары без картинки, у которых сейчас 📦.
- `batches/` — готовые промпты, два вида пачек по 9 товаров:
  - `batch-NNN.md` — **без надписей**: одна картинка на оба языка, в промпте прямой запрет на
    любой текст. `batch-001`…`batch-014` и `text-001`…`text-004` (с английскими версиями) уже сгенерированы; их ячейки с надписями перерисовываются
    в текстовых пачках (в таблице помечено «перерисовывается в text-…»);
  - `text-NNN.md` — **с надписями на упаковке**: русская версия, затем в том же чате английская.
- `manifest.json` — «пачка → ячейка → товар», вход для импорта.

Пересобрать после правки `candidates.json`: `npx tsx scripts/emoji-batches.ts`. Скрипт падает,
если товар уже есть в каталоге, повторяется или указан в несуществующей категории.

## Как генерировать

1. Для каждой пачки — **новый чат** в Gemini (иначе модель дорабатывает прошлую картинку). По
   обязательно приложить все четыре образца из `style-refs/`: `zucchini.webp` (batch-001, ячейка 1),
   `lentils.webp` (batch-001, ячейка 2), `honey.webp` (batch-010, ячейка 4) и
   `kefir.webp` (text-001, ячейка 2, русская этикетка).
2. **Пачка без надписей** (`batch-NNN.md`): вставить промпт, сохранить как
   `~/Downloads/clickmoji-batches/batch-NNN.png`. Вторая версия не нужна.
3. **Пачка с надписями** (`text-NNN.md`): промпт «Русская версия» → сохранить как `text-NNN.png`;
   затем **в том же чате** промпт «Английская версия» → сохранить как `text-NNN-en.png`. Gemini
   правит свою же картинку, поэтому рисунки совпадают и меняются только надписи.
4. Ячейки читаются слева направо, сверху вниз, как в таблице пачки.

В приложении русская картинка лежит в `products.imageUrl`, английская — в словаре `products.localizedImages` под ключом `en` (колонка `imageUrlEn` дублируется только для отката на прежний выпуск).
При смене языка меняется только картинка, у которой есть английская версия; картинки без надписей
одни на оба языка.

Если ячейка не удалась, достаточно перегенерировать пачку целиком или отдать одиночную картинку
`batch-NNN-C.png` (`text-NNN-C.png` и `text-NNN-C-en.png`), где C — номер ячейки.

## Импорт в приложение

Скрипт режет сетки, нормализует картинки (WebP 256 с прозрачностью) и привязывает их к товарам
каталога. Без `--apply` он ничего не пишет: в `~/Downloads/clickmoji-batches/preview/` появляются
картинки, копии четырёх образцов из `style-refs/` и `preview.html` — сверху четыре образца стиля,
у каждой ячейки картинка в размере списка телефона (`56 px`) и крупно (`128 px`) на светлом и
тёмном фоне, `ru` и `en`, число «детальность», пометка строго выше порога и что будет сделано
(привязать к существующему товару / создать товар / только библиотека). Пометка служит визуальной
подсказкой и не запрещает загрузку.

```bash
npx tsx scripts/emoji-import.ts --batch 001,002,003,text-001 [--detail-threshold 14000]
```

Это C3 preview-only: каталог не открывается, а `DATABASE_URL`, унаследованный из окружения, игнорируется.
`--out` должен быть другой папкой, чем `--dir` (в том числе через симлинк или жёсткую ссылку);
иначе скрипт завершится до первой записи и исходные сетки останутся нетронутыми.

Сверка с каталогом (C6, opt-in) — только с локальной БД и явным флагом. Без `DATABASE_URL` флаг
завершает команду ошибкой, а не тихо пропускает сверку:

```bash
DATABASE_URL='<локальная БД>' npx tsx scripts/emoji-import.ts --batch 001,002,003 --check-catalog
```

Запись (оператор, после миграции из `docs/emoji-library-migration.md`; `--apply` сам включает сверку):

```bash
DATABASE_URL='<прямой URL>' UPLOADTHING_TOKEN='<токен>' npx tsx scripts/emoji-import.ts --batch 001,002,003 --apply
```

- Каждая ячейка — запись библиотеки с ссылкой `batch-NNN#C` (английская — `batch-NNN#C:en`).
  Повторный запуск ничего не загружает заново и только перепривязывает товары.
- Импорт не удаляет файлы из хранилища. Если запись библиотеки не удалась уже после загрузки
  (или конфликт заставил отказаться от своей картинки), загруженный файл остаётся без записи: он
  может быть неиспользуемым. Причина — адрес мог уже попасть в историю покупок (`ListHistoryItem`
  хранит `productImageUrl` и `productImageUrlEn`), а по одной загрузке нельзя доказать, что файл
  принадлежит только этой попытке; параллельная публикация того же адреса тоже не видна при
  проверке (AGE-1667 B3). Цена: при повторном запуске такая ячейка загрузится заново и возникнет
  лишний файл. Импорт такие файлы не чистит; команда `db:files` историю не учитывает, поэтому
  удалять их можно только вручную после проверки `ListHistoryItem`.
- Товар ищется по названию (регистр и «ё» не важны) среди общего каталога; если нет — создаётся в
  категории из манифеста с emoji категории.
  Если в каталоге несколько товаров с одним названием, ячейка остаётся только в библиотеке, а
  предпросмотр и отчёт перечисляют эти товары — нужный выбирается в админке.
- Белые области внутри предмета по умолчанию сохраняются (это может быть этикетка или белая
  мякоть). Вырезаются они только у ячеек с `gaps: true` в `candidates.json` — там, где просветы
  проверены глазами (зелень, гроздь черри, дырка пончика). Чтобы добавить ячейку, поставьте флаг,
  пересоберите пачки и снова посмотрите предпросмотр.
- Плохую ячейку можно заменить одиночной картинкой `batch-NNN-C.png` (и `batch-NNN-C-en.png`) и
  запустить импорт этой пачки ещё раз. Старая картинка останется в хранилище; замена через
  повторную загрузку — с `--apply` по той же ссылке пока не перезаливается (удалите запись
  библиотеки в админке или напишите мне).

## Очередь 144 цели (AGE-1667, C6)

Снимок каталога на 2026-11-25 (`catalog-snapshot-2026-11-25.json`, только названия) даёт 144 цели:

- 123 товара без картинки и 2 варианта без картинки — картинка «новая» (`update-image`);
- 14 категорий без картинки — тоже `update-image`;
- 5 категорий, у которых картинка уже есть: Напитки, Крупы и макароны, Орехи и Сухофрукты,
  Масла и соусы, Рыба и морепродукты — **замена** (`replace`), только по явному разрешению (см. ниже).

Очередь выстроена так, чтобы 139 прежних целей остались на тех же местах (пачка и ячейка): новые
5 категорий добавлены в конец, отдельной пачкой `queue-011` (ячейки 1–5).

- `queue-candidates.json` — список целей с полем `action`; проверяется против снимка: каждая цель
  ровно один раз, названия и категории совпадают, `replace` — ровно у категорий с картинкой, у
  категории промпт просит «exactly three most recognizable» (ровно три самых узнаваемых товара
  группы в одной композиции).
- `queue/queue-NNN.md` — пачки без надписей: 11 штук (`queue-001`…`queue-010` по 9 ячеек, `queue-011` на 5).
- `queue/queue-text-NNN.md` — пачки с надписями на упаковке: 6 штук (5 по 9 и одна на 4 ячейки).
  Надписи: русская версия, затем английская в том же чате. 49 товаров.
- Итого: 17 пачек на 144 цели (11 без надписей — 95 ячеек, 6 с надписями — 49 ячеек).
- `queue-manifest.json` — «пачка → ячейка → цель»; у варианта указан `parent`, у категории название — её
  собственное, у замены `"action": "replace"`.

Пересобрать после правки `queue-candidates.json`: `npx tsx scripts/emoji-queue.ts`.

Предпросмотр и импорт — те же команды, пачки указываются как `queue-001`, `queue-text-001`, `queue-011`:

```bash
npx tsx scripts/emoji-import.ts --batch queue-001,queue-002,queue-text-001
```

Предпросмотр сверяет каждую цель с каталогом и печатает итог: целей, найдено, ненайденных,
неоднозначных (неоднозначные перечисляются поимённо) и число замен. Ненайденная цель картинку не
создаёт. Без `--apply` ничего не записывается.

### Замена картинок пяти категорий

Замена — это перезапись картинки, которая уже стоит в каталоге, поэтому она работает только с явным
разрешением оператора. Разрешение — файл с прежним состоянием каждой категории: адресом картинки и
флагом «своя картинка» (`isCustom`). Оба значения оператор берёт из базы, из строки категории в
`categories`: поле `imageUrl` и поле `isCustom`. Файл **не коммитится**: держите его вне репозитория,
например `~/Downloads/clickmoji-batches/replace-auth.json`.

```json
{
  "replacements": [
    {
      "category": "Напитки",
      "expectedImageUrl": "https://<старый адрес картинки>",
      "expectedIsCustom": true
    },
    {
      "category": "Крупы и макароны",
      "expectedImageUrl": "https://<старый адрес картинки>",
      "expectedIsCustom": true
    },
    {
      "category": "Орехи и Сухофрукты",
      "expectedImageUrl": "https://<старый адрес картинки>",
      "expectedIsCustom": true
    },
    {
      "category": "Масла и соусы",
      "expectedImageUrl": "https://<старый адрес картинки>",
      "expectedIsCustom": true
    },
    {
      "category": "Рыба и морепродукты",
      "expectedImageUrl": "https://<старый адрес картинки>",
      "expectedIsCustom": true
    }
  ]
}
```

- Ровно одна запись на каждую заменяемую категорию выбранных пачек; только `category`,
  `expectedImageUrl` и `expectedIsCustom` (`true` или `false`, как в базе); адрес — абсолютный
  `https://`, без пробелов.
- Без `--replace-auth` предпросмотр работает и показывает условия замены, а `--apply` с заменами
  отказывается **до загрузки** файлов, с сообщением, какой записи не хватает или что не разобрано.
- Запись категории — одно условное обновление: «заменить, если текущие адрес и флаг равны прежним».
  Флаг меняется на `true` вместе с картинкой. Если категория уже содержит новый адрес этой пачки и
  флаг `true`, а её библиотечная запись принадлежит этой ячейке (повторный или параллельный запуск),
  ячейка считается выполненной и ничего не пишется. Пустой адрес без такой записи — не повтор, а
  конфликт до загрузки. Если адрес или флаг изменены вручную или другой пачкой (в том числе флаг
  выключен вручную при том же адресе), ячейка получает конфликт, картинка категории не перезаписывается.

```bash
npx tsx scripts/emoji-import.ts --batch queue-011 --replace-auth ~/Downloads/clickmoji-batches/replace-auth.json
DATABASE_URL='<прямой URL>' UPLOADTHING_TOKEN='<токен>' npx tsx scripts/emoji-import.ts --batch queue-011 --replace-auth ~/Downloads/clickmoji-batches/replace-auth.json --apply
```

Импорт ничего не удаляет ни в хранилище, ни в каталоге, в том числе при ошибках. Загруженная, но не
привязанная картинка остаётся в хранилище (см. выше про B3).

Проверки: `npm run test:queue-replace-postgres` (одноразовая база в Docker, 144 цели синтетическими
пачками с подменной загрузкой; замены, ручная правка, параллельный запуск, повтор, предпросмотр).

## DECISIONS (С3 — детальность и предпросмотр)

- **Образцы стиля.** Показываются все четыре файла из `docs/emoji-batches/style-refs/` (`zucchini.webp`,
  `lentils.webp`, `honey.webp`, `kefir.webp`) вместо трёх из черновика плана: при расхождении с планом
  приоритет у спецификации С3 и `queue`.
- **Метрика «детальность» и единицы.** Размер файла в **байтах** (`bytes`, отображается как `Б`)
  после одинаковой канонической нормализации функцией `normalizeEmojiImage` (`src/lib/services/emoji-image-normalize.ts`,
  реализация меры — `src/lib/services/emoji-detail.ts`). Параметры канонической нормализации:
  - холст `256 × 256` (`NORMALIZED_EMOJI_SIZE = 256`), прозрачный фон (`alpha = 0`);
  - удаление фона (доверие собственной альфе при прозрачной границе `>= 50%` пикселей рамки с `alpha < 32`,
    иначе flood fill с краёв при `LIGHT_SEED_MIN = 200`, `FLOOD_THRESHOLD = 40`, `EDGE_BLUR_SIGMA = 1.2`);
  - рабочее ограничение декодера `MAX_INPUT_PIXELS = 4096 * 4096`, `WORK_SIZE = 1024`;
  - кадрирование по объекту (`ALPHA_CUTOFF = 20`, морфологическое открытие `SPECK_RADIUS = 2`) и
    масштабирование `lanczos3` до `86%` стороны (`FILL = 0.86`, `220 × 220` + ровные поля);
  - кодирование `WebP` (`quality: 82`, `effort: 6`).
    Один и тот же расчёт используется и в предпросмотре импорта (`scripts/emoji-import.ts` через
    `readBatchImages` → `detailScoreFromNormalized`), и в аудите экспорта каталога (`scripts/emoji-detail-audit.ts`
    через `measureEmojiDetail`).
- **Порог и правило сравнения.** Порог по умолчанию: **`14000` Б** (`DEFAULT_DETAIL_THRESHOLD_BYTES = 14000`,
  переопределяется флагом `--detail-threshold <bytes>`). Пометка ставится **строго выше** порога
  (`score > threshold`; равенство `score === threshold` не помечается) и служит только визуальной
  подсказкой — импорт не блокируется. Обоснование `14000` Б: после канонической нормализации четыре
  образца стиля дают `5664` Б (`kefir.webp`), `6528` Б (`zucchini.webp`), `10876` Б (`lentils.webp`) и
  `10934` Б (`honey.webp`, максимум образцов); порог `14000` Б (~`+28%` к максимуму образцов) оставляет
  запас для гладких 3D-иконок со сложной палитрой и выделяет действительно перегруженные мелкой
  фактурой или шумные старые картинки (в каталоге `catalog-export-2026-11-25.json` это 12 верхних из 222
  успешно измеренных основных картинок товаров: `14262–31470` Б — зелень с мелкими листьями, плотные
  гроздья/ягоды и устаревшие 1024×1024 PNG).
- **Ограничения меры.**
  1. Устаревшие картинки каталога в `catalog-export-2026-11-25.json` хранятся в разных форматах
     (82 PNG `1024×1024`, 1 JPEG `225×225`, 181 WebP `256×256`), поэтому каноническая нормализация
     обязательна: без неё 1024×1024 PNG весят 340–697 КБ независимо от детальности.
  2. Так как `normalizeEmojiImage` кодирует в lossy WebP (`quality: 82`), повторная нормализация уже
     сжатого WebP `256×256` из хранилища сдвигает размер на ~2–4% (например, для `style-refs`:
     `kefir.webp` `5758 → 5664` Б, `zucchini.webp` `6704 → 6528` Б, `lentils.webp` `11274 → 10876` Б,
     `honey.webp` `11244 → 10934` Б). На границе порога это стоит учитывать как погрешность второго
     прохода.
  3. Для ячеек манифеста с `gaps: true` предпросмотр применяет `clearEnclosedGaps: true`, тогда как аудит
     готового каталога не имеет сведений о `gaps` и нормализует с `clearEnclosedGaps: false` (на уже
     прозрачных 256×256 WebP это не влияет).
  4. Скрипт аудита каталога (`scripts/emoji-detail-audit.ts`) работает без подключения к БД и без
     `.env`; кэш скачанных картинок и файлы отчёта запрещено размещать внутри репозитория. Любая ошибка
     скачивания/декодирования (например, HTTP 404) фиксируется как `UNKNOWN`, а при неполном результате
     скрипт завершается с ненулевым кодом (`1`), сохраняя полный отчёт в `--out`.
- **Режимы импорта (B1, C3 preview-only).** Предпросмотр без `--apply` и без `--check-catalog` не открывает
  каталог и не читает `DATABASE_URL`: унаследованный DSN оператора не может попасть в запрос. Сверка с
  каталогом — отдельный opt-in `--check-catalog` (локальная БД); без `DATABASE_URL` он завершается
  ошибкой (fail closed). `--apply` включает сверку сам и по-прежнему требует `DATABASE_URL` и
  `UPLOADTHING_TOKEN`. Тест подаёт синтетический DSN на закрытый локальный порт и проверяет, что
  предпросмотр завершается без подключения (`src/lib/services/emoji-import-guards.test.ts`).
- **Разделение входа и выхода (B2).** До первой записи скрипт проверяет: `--out` не совпадает со
  входным `--dir` ни напрямую, ни через симлинк (канонические пути); ни одно планируемое имя выходного
  файла не является символьной ссылкой и не указывает на ту же запись диска, что исходная картинка или
  образец стиля (жёсткая ссылка). Типичный подкаталог `--dir/preview` разрешён. Исходные байты
  проверяются тестами. Отказ даёт ошибку до загрузки и записи, а не перезапись.
- **Корень инструмента и пути (B3).** Корень репозитория вычисляется из расположения модуля
  (`TOOL_REPO_ROOT` в `src/lib/services/safe-paths.ts`), а не из cwd. Проверка `assertPathOutsideRepo`
  использует канонические пути: существующие компоненты разрешаются через `realpath`, висячие симлинки
  переходятся по цели, ещё не созданные каталоги дописываются к каноническому предку. Отказ случается
  до создания кэша и отчёта. Существующие выходные файлы отчёта (`detail-report.json`, `.md`) и
  файлы кэша проверяются тем же способом, в том числе перед записью в загрузчике кэша.

### Команды воспроизведения (С3)

```bash
# Предпросмотр сеток оператора во временной папке (только чтение исходных сеток; каталог не открывается;
# --out должен отличаться от --dir; DATABASE_URL из окружения не читается)
npx tsx scripts/emoji-import.ts \
  --dir ~/Projects/clickmoji-batches \
  --out "${TMPDIR:-/tmp}/clickmoji-c3-preview" \
  --detail-threshold 14000

# Аудит 227 основных картинок товаров из экспорта каталога (скачивание/кэш и отчёт только вне репо)
npx tsx scripts/emoji-detail-audit.ts \
  --input ~/.local/share/dev-harness/artifacts/clickmoji/catalog-export-2026-11-25.json \
  --cache-dir "${TMPDIR:-/tmp}/clickmoji-c3-cache" \
  --out "${TMPDIR:-/tmp}/clickmoji-c3-audit" \
  --scope products \
  --detail-threshold 14000

# Адресные офлайн-тесты трёх блокеров (без сети, без рабочей БД, без записи в ~/Projects/clickmoji-batches)
npx vitest run src/lib/services/safe-paths.test.ts src/lib/services/emoji-import-guards.test.ts src/lib/services/emoji-detail.test.ts
```
